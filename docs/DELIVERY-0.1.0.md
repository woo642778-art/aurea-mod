# Aurea Studio 0.1.0 delivery record

Packaged locally on 2026-10-16: `Aurea-Studio-0.1.0-unsigned.ipa`, 79,649,814 bytes, SHA256 `b93163ef55e8d1d55812fbde6a3943d9fe69f5fd065c9f5c9679b0bc070cd336`. The original IPA and user media were not uploaded to this repository. The result needs all nested code re-signed before device installation.

This is an experimental offline EffectCraft workspace inside the existing Aurea application, with a source-media and rendered-media bridge. Full native effect/timeline parity and editable project interchange are NOT implemented. Physical-device testing of the original Aurea engine has NOT been performed.

The original uploaded Aurea 0.1.9 (2185) ARM64 executable was directly analyzed: 1,660 Objective-C classes, 499 AureaEngine instance methods, and all 10 bridge selector encodings confirmed. Existing expression, puppet, mask, camera, tracking, keyframe and rig APIs were not incorrectly labeled as absent. Static API presence is not proof of behavioral equivalence.

A fresh browser context restored exact original PNG media bytes and identical rendered pixels. The runtime enumerated 307 distinct effects and 731 commands; this does not mean every effect was individually correctness-tested.

Back up existing Aurea projects before installation; the bundle identifier remains com.aurea.aurea. Open a test project, select image media, tap the draggable EC button, import the source into Studio, export a PNG, then use the native library action to add it as a new Aurea layer. Original Aurea effects and keyframes do not transfer. A .ecproj does not embed media; retain the original media or use a portable .aureastudio.zip (96 MiB maximum). Single transfers are capped at 256 MiB. GPU frame workers are conservatively disabled and the touch preview uses a 640-pixel maximum side; native Metal or high-frame-rate preview performance is not promised. All codecs, long/high-resolution projects, every effect and real-device original-engine synchronization remain unverified.
